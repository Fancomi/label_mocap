# 极向量柄 / 末端柄 单活动切换 UX 设计

- 日期：2026-06-23
- 分支：`feat/pole-vector-controllers`（在已实现的极向量控制器之上的 UX 增量）
- 前置：[极向量控制器设计](2026-06-23-pole-vector-controllers-design.md) 已实现并通过 183 项 web 测试
- 内核：`smpl_edit`（label / pcd 共享）

## 1. 背景与问题

极向量控制器初版在选中 IK 肢体时**同时显示两个三轴平移箭头**（末端目标柄 + 极向量柄）。实测交互混乱：两套箭头叠在一起，用户分不清在拖哪个。

设计师要求改为：

1. 进 IK 时柄默认在腕/踝（末端柄），**极向量柄不显示三轴箭头**。
2. 通过**点击**在末端柄与极向量柄间切换。
3. 两种选中状态用**有差异的方式**显示以体现区别。

## 2. 设计决策（已确认）

| 维度 | 决策 |
|---|---|
| 切换触发 | **被动小球占位 + 点选切换**——任一时刻只有一个柄显示三轴箭头（活动柄），另一个缩成无箭头的可点选占位符。点占位符 → 它升为活动柄，原活动柄降为占位符 |
| 视觉区分 | **颜色 + 形状都区分**（见 §4） |

不引入热键 / 不新增 UI 按钮；切换完全靠点选 3D 场景里的占位符。

## 3. 交互模型与状态

**核心不变式：任一时刻 IK 肢体上只有一个柄带三轴箭头（活动柄），另一个是无箭头占位符。**

- **进 IK 选中肢体**：`activeHandle = 'end'`。末端柄出箭头（腕/踝），极向量柄为青色小球占位。
- **点占位符**：把 `activeHandle` 设为**被点中那个柄的身份**（点末端立方体 → `'end'`；点极向量球 → `'pole'`），而非盲目翻转——因为极向量球在活动态仍作头标可见，盲目翻转会误判。设为已是当前值时为无操作。新活动柄出箭头，原活动柄降为占位符，`requestSync()` 重挂。
- **切换肢体 / 关 IK / 切到 Pose·Root·Bbox 模式**：`activeHandle` 重置回 `'end'`。
- **同一肢体跨 syncUI**：保持当前 `activeHandle`（不每帧重置，否则播放/重绘会把用户的选择冲掉）。

**状态归属**：`activeHandle` 状态机（值 `'end' | 'pole'` + 绑定链名）持在 `ik_plugin` 闭包内。这是唯一新增的可变状态。

**解算零改动**：拖活动柄的解算沿用已实现路径——末端柄 → `solveTo`（消费存储 pole）；极向量柄 → `solveToPole`（末端锁定、仅旋转弯折平面）。`ik_controller` / `ik_solver` 不改。

## 4. 视觉方案（颜色 + 形状都区分）

每个柄有「活动」「占位」两态，共四种外观：

**末端目标柄**
- 活动：标准三轴平移箭头，**RGB 轴色**（红=X / 绿=Y / 蓝=Z）——现有 TransformControls 默认，不改。
- 占位：**中性灰白小立方体**，无箭头，可点选。立方体形状区别于极向量的球。

**极向量柄**
- 活动：三轴平移箭头，整体**染成青色系**（弱化 RGB，标示「非普通平移柄」），柄心保留**青色小球**作头标。
- 占位：纯**青色小球**（沿用现状那颗），无箭头，可点选。

**区分逻辑**：
- 颜色：末端 = RGB，极向量 = 青。
- 形状：占位态末端 = 立方体、极向量 = 球；即使都退成占位符也不混淆。
- 活动态都带三轴箭头（功能都是 translate），靠颜色分；占位态靠形状 + 颜色双重分。

## 5. 拾取实现

现有 `joint_picker.js` 的 `JointPicker` 在 pointerup 做点击判定（4px 阈值），但它只 raycast 关节球、且被 `canPick: () => !engageGuards.some(g => g.isEngaged())` 闸住。占位符既不是关节球，又会在「活动柄存在」时落入 engage 闸，故**不能直接复用** JointPicker。

方案——`ik_plugin` 内部自挂一条轻量 pointerup 监听：

1. 沿用 `JointPicker` 的 4px 点击阈值（pointerdown→up 位移 < 阈值才算点击，否则是拖拽）。
2. 仅 raycast 两个柄的标识 mesh（末端立方体 / 极向量球）——不测活动柄的箭头，天然不与活动箭头抢事件。注意极向量球在活动态也可见（作头标），故命中后按**被点 mesh 的身份**设 `activeHandle`，而非翻转。
3. 命中标识 mesh **且**当前无柄 `isDragging()` → 将 `activeHandle` 设为该 mesh 对应身份（已是当前值则无操作）、重挂两柄、`requestSync()`。
4. 活动柄的 TransformControls 先消费指针；只有点落在标识 mesh（活动箭头未命中）才触发切换。

**显隐管理**：占位 mesh 的创建/显隐由 `ik_plugin` 统一管（连同 `activeHandle` 状态）。Handle 类只负责「箭头显隐」，职责清晰。`syncHook` 的 IK 分支按 `activeHandle` 决定谁出箭头、谁出占位；fall-through 两柄全 detach + 两占位 mesh 移除。

## 6. 接线与测试策略

**接线**（仍零 app.js 改动）：
- 改动集中在 `smpl_edit/ik_plugin.js`（activeHandle 状态机 + 占位 mesh + 切换 raycast + syncHook 分支）与 `smpl_edit/pole_handle.js`（活动态染青 + 箭头显隐分离）。
- 末端柄占位立方体：在 plugin 内统一管两个占位 mesh，`ik_handle.js` 仅加「箭头显隐」开关。
- `ctx` 已提供 scene/camera/canvas/controls，无需新字段 → label/pcd 自动同获。

**测试策略**（CLAUDE.md：纯逻辑单测，three.js/DOM 浏览器验）：
- **可单测**：`activeHandle` 状态机抽成无 DOM 的小对象 —— 测「默认 'end'」「set('pole')/set('end') 切换」「重复 set 同值为无操作」「切肢体/关 IK 重置回 'end'」「同肢体跨 sync 保持」。
- **浏览器手验**（补进现有清单）：占位 mesh 点选切换、活动柄染色、箭头显隐、4px 点击阈值不误触发、拖活动箭头时不切换。
- 解算与存储不受影响（控制器零改动），原极向量 7 任务单测继续保证核心不变式。

## 7. 范围边界

- 仅改「两柄如何显示与切换」；不改解算、不改存储格式、不改 `pole_vectors` 数据模型。
- 不加热键、不加 UI 按钮——切换只靠点选占位符。
- 不动 `JointPicker`（新挂独立监听，避免污染关节拾取语义）。
